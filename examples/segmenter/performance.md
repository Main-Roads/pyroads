# Segmenter Performance Record

The repeatable harness is `examples/segmenter/benchmark.py`.
Run it with:

```text
uv run python examples/segmenter/benchmark.py --repeats 7
```

All timings are warm medians after one warm-up call, on Python 3.13.13. The synthetic workloads are generated by the harness:

- category operations: 128,000 rows;
- overlay: 8,000 original rows and 4,000 additional rows;
- cross-sections: 1,000 intervals across four lanes;
- max-length splitting: 32,000 rows.

## Pre-optimization pyroads baseline

These measurements were captured before the optimization pass. The overlay and cross-section values came from the audit workload with allocation tracing enabled, so they are directional rather than directly comparable to the warm harness values.

| Operation | Runtime | Output rows |
| --- | ---: | ---: |
| Category true discontinuities | 21.5 ms | 128,000 |
| Overlay | 200.2 ms | 8,088 |
| Cross-sections, four lanes | 2,815.7 ms | 4,000 |
| Max-length splitting | 66.6 ms | 3,200 |

A larger pre-optimization cross-section workload with 2,000 intervals per lane took 10,563 ms.

## Post-optimization pyroads baseline

| Operation | Runtime | Output rows |
| --- | ---: | ---: |
| Category SLK discontinuities | 16.8 ms | 128,000 |
| Category true discontinuities | 16.7 ms | 128,000 |
| Overlay | 59.3 ms | 8,088 |
| Cross-sections, four lanes | 72.8 ms | 4,000 |
| Max-length splitting | 28.7 ms | 3,200 |

The cross-section path was also measured at 2,000 intervals per lane: 202.2 ms.

## Old repository comparison

The old `segmenter` source was run directly with the same generated data and pandas version where possible:

| Operation | Old segmenter | Pyroads | Relative result |
| --- | ---: | ---: | ---: |
| Category SLK discontinuities | 69.7 ms | 16.8 ms | 4.1x faster |
| Category true discontinuities | 71.5 ms | 16.7 ms | 4.3x faster |
| Max-length splitting | 1,356.4 ms | 28.7 ms | 47.3x faster |
| Cross-sections | `KeyError: 0` | 72.8 ms | Old path fails |
| Overlay | `KeyError: 0` | 59.3 ms | Old path fails |

The old failures are caused by its positional `Series` indexing in validation under the current pandas version. They are recorded as compatibility failures, not converted into timing claims.

## Equivalence checks

On identical small synthetic inputs:

- SLK discontinuity output: serialized output identical;
- true-discontinuity output: serialized output identical;
- max-length split: interval and measure values identical; old output additionally contains `key_0`;
- cross-sections: the optimized implementation passes the existing cross-section fixtures and produces valid output for the old failure workload.

Results should be re-recorded on production-sized road datasets before treating these synthetic ratios as universal.
